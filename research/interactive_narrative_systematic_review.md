# 面向 `my-rpg` 体验改进的 LLM 互动叙事系统综述

**检索截止**：2026-08-21  
**协议版本**：1.0  
**性质**：项目决策综述，不是学术投稿，也不追求为了“研究感”增加系统复杂度。

## 结论先行

当前证据不支持把游戏改成“每回合多个 Agent 讨论、批评、整段重写”。更可靠的方向是：

1. **程序保存结构化事实、时间、人物知识与玩家承诺；模型不能只靠聊天历史重建世界。** [A/B]
2. **规划要分层、短视窗、可更新，保存的是当前承诺与场景条件，而不是锁死几十回合的大纲。** [A/B]
3. **玩家能动性不是“有四个按钮”，而是玩家行为对人物反应、关系、状态或后续可能性留下可观察影响。** [A/B]
4. **多 Agent 只在高风险/高互动节点选择性使用；普通对话保持一次流式写作。** [B]
5. **一致性检查先用程序规则和证据定位；LLM critic 只能处理被定位的问题，不能当唯一裁判。** [A]
6. **评估必须用相同存档的多回合 A/B 和真人盲评；自动分数只做报警。** [A]

这意味着现有“剧情规划 Agent + 场景写手”不是方向错误，但 `StoryRuntime` 还过于像离线小说大纲，记忆检索也仍偏“把相关文本塞回 prompt”。下一轮应先补可靠状态与测试，再收窄规划器职责，最后才试验选择性批评或多角色协作。

## 方法与筛选

五组查询覆盖长篇规划、互动戏剧/能动性、角色持续性、记忆/状态、评价可靠性。查询捕获 48 条记录，去重后 42 条；标题/摘要排除 6 条，36 条进入全文或扩展材料核验，全文后排除 5 条，最终综合 31 条。详细查询和逐条决定分别见：

- `interactive_narrative_search_log.md`
- `interactive_narrative_screening.csv`
- `interactive_narrative_evidence_matrix.csv`

这是单人项目综述，不声称双人筛选，也不把搜索接口返回的排序候选假装成数据库全量结果。研究任务高度异质，未做统计合并。

## 1. 长篇规划确实有用，但“越细越好”不成立

### 支持证据

[Re³](https://aclanthology.org/2022.emnlp-main.296/) 把总计划和当前故事状态反复注入生成，并通过候选重排、事实编辑改善 2,000 字以上故事；同基模人工评价中，总体情节连贯提高 14 个百分点、前提相关提高 20 个百分点。[DOC](https://aclanthology.org/2023.acl-long.190/) 进一步使用层次详细大纲和控制器，相对 Re³ 在情节连贯、大纲相关和有趣性上分别报告 22.5、28.2、20.7 个百分点的绝对提升。这给“规划与文案分开”提供了较强的离线证据。[A]

[DOME](https://aclanthology.org/2025.naacl-long.63/) 的关键进步不是再写一份更长大纲，而是把粗计划和局部细化融合，在生成过程中动态更新，并用时间知识图维护已发生内容；其消融显示移除记忆模块时冲突和人评都会恶化。[B]

### 反证与边界

这些论文生成的是离线长篇，不需要每回合接受玩家拒绝、绕路、无视任务或改变身份。DOC 也暴露了控制的代价：详细叶节点本身可能不好，强控制可能使文本狭窄、重复。互动系统若把“必须发生的节点”当成唯一正确路线，就会把论文里的 coherence 变成玩家感受到的强塞剧情。

因此，对本项目有效的不是“更完整的大纲”，而是两层结构：

- **长期层：少量可验证承诺、开放问题、人物目标和可放弃线程；**
- **眼前层：2–4 回合有效的场景契约，写明因果来源、可公开信息、可用行动空间和停点。**

玩家改变局面后，局部计划应失效并重算，而不是由写手设法把旧节点重新包装。

## 2. 互动叙事需要选择性导演，不需要每回合全员 Agent

[IBSEN](https://aclanthology.org/2024.acl-long.88/) 和 [From Role-Play to Drama-Interaction](https://aclanthology.org/2024.findings-acl.196/) 表明“导演维护整体目标、演员保持局部角色行为”可以生成更可控的互动剧本；但前者主要依赖一个改编场景，后者只有 3 个手工脚本，不能证明在任意网文世界和数十回合自由输入下稳定。[B]

[Towards Enhanced Immersion and Agency](https://aclanthology.org/2025.acl-long.546/) 给出了更贴近产品的定义：agency 是角色对玩家意图产生**有意义的反应或转变**，而不是只展示选项。它也给出重要工程边界：复杂的剧作生成使用多候选、批评、投票和多轮细化，耗时约为基础生成的 10–12 倍；论文因此采用 Director-Actor、One-for-All 与 Hybrid 三种运行方式，不是所有场景都需要同样深度。[A/B]

[Player-Driven Emergence](https://arxiv.org/abs/2404.17027) 的 28 名玩家实验说明，开放交互会产生原设定外但可能有趣的新叙事节点，尤其对偏好探索/发现的玩家。固定故事只能是约束和材料，不应成为唯一合法轨道。[B]

对 `my-rpg` 的直接含义：

- 日常交谈、购物、移动、休息：状态检索后由单一写手流式生成；
- 玩家改变关系、揭示关键事实、跨场景、触发高风险行动：刷新场景契约；
- 只有发生难以用程序判定的“玩家意图 vs NPC目标 vs 已有承诺”冲突时，才调用额外导演/裁定；
- 不为每个 NPC 启动独立模型调用。NPC 的信念、欲望、意图可以结构化保存，但表演仍可由当前写手一次完成。

## 3. 记忆问题不是上下文长度问题，而是状态、选择与边界问题

[LoCoMo](https://aclanthology.org/2024.acl-long.747/) 用平均约 600 轮、16K token、最多 32 个 session 的对话评估长期记忆：长上下文和 RAG 能改善结果，但仍显著落后人类，时间和因果推理尤其弱。[B]

[TimeChara](https://aclanthology.org/2024.findings-acl.197/) 说明检索更多文本甚至会让角色知道“不该在当前时间点知道的未来信息”；朴素 RAG 不是安全升级，检索必须先按时间截止、角色参与和知识来源过滤。[B]

[Memory-Driven Role-Playing](https://aclanthology.org/2026.findings-acl.1175/) 将角色记忆拆成 Anchoring、Selecting、Bounding、Enacting：先确定角色核心，再选相关记忆，再判断知识/行为边界，最后表演。结构化记忆 schema 的贡献通常大于单纯加长角色卡。但它主要评 NEXT-TURN，不能直接证明 50 回合后仍稳定。[B]

[CharacterBox](https://aclanthology.org/2025.naacl-long.323/) 使用 BDI（信念、欲望、意图）和环境更新来评价角色轨迹；[Dynamic Persona Coherence](https://aclanthology.org/2026.acl-long.1336/) 则区分长期身份、中期压力/意义、短期情绪。两者共同指出：把“角色一致”理解成永远重复同一种语气，会产生机器人式僵硬；真实一致性是稳定身份约束下的合理变化。[B]

因此记忆至少要拆成：

| 层 | 程序保存什么 | 检索条件 | 不允许做什么 |
|---|---|---|---|
| 正史 Canon | 世界规则、已确认身份、物品、地点、死亡/存活 | 总是按需编译 | 被摘要或正文覆盖 |
| 事件 Timeline | 谁在何时何地做了什么、原因与结果 | 实体+时间+因果 | 把传闻当事实 |
| NPC Belief | 某 NPC 亲历/被告知/推断的内容及置信度 | 当前 NPC+信息来源+时间 | NPC 间自动共享 |
| 承诺 Commitment | 玩家/NPC 接受、拒绝、承诺、期限、完成条件 | 主体+状态+截止条件 | 忘记拒绝后换皮重发 |
| 关系/心理 Dynamic | 中期关系/压力与短期情绪 | 相关人物+近期事件 | 把短期生气写成永久人格改变 |
| 章节摘要 | 一段时期的高层过程 | 场景/章节召回 | 作为权威数值或精确事实 |

语义相似只负责“找候选”，时间、角色可知性、事实状态和来源负责“能否注入”。

## 4. 结构化承诺比“让模型自己记住剧情”更可靠

极新的 [NCP-Bench](https://arxiv.org/abs/2608.08160) 直接模拟开放玩家与叙述者最多 100 回合的互动：100 个环境都有事实账本和剧情承诺。其预印本报告，最佳模型在 20 回合后保持无冲突的存活率也只有 42%，各模型最终事实冲突率为 40%–68%。论文同时强调：逻辑一致只是好故事的必要条件，不是充分条件。[B，预印本]

[ConStory-Bench](https://arxiv.org/abs/2603.05890) 的 2,000 个长篇提示把错误分成时间/情节、人物、世界、事实细节、叙述风格等 19 个子类，并发现事实和时间问题最常见，错误常在长文中段出现。[B，预印本]

这两项结果支持两个不同闸门：

1. **硬事实/硬承诺**：程序必须能判定，如物品数量、NPC是否知道、玩家是否拒绝、某人是否死亡；违反则拒绝 patch 或局部重生成。
2. **软剧情承诺**：例如“这段关系需要逐步修复”“某问题尚未回答”；它们帮助连续性，但允许被玩家行动修改、暂停或放弃。

不能把所有未来剧情都写成硬承诺，否则系统会为了“完成率”牺牲玩家自由。

## 5. 常开 critic 和整段重写并不可靠

[CritiCS](https://aclanthology.org/2024.emnlp-main.1046/) 的多批评者在离线故事创造性和吸引力上有收益，但部分小样本一致性比较并不稳定，论文也指出宽泛、互不相关的批评会破坏连贯。[B]

[Mary, the Cheeseburger-Eating Vegetarian](https://aclanthology.org/2026.eacl-long.280/) 发现，LLM 对违反常识场景的错误较敏感，却难以稳定识别“已经设定为素食者却点汉堡”这类人物特质冲突；推理模型和思维链没有消除问题。[A]

跨任务的 [Beyond Single-shot Writing](https://aclanthology.org/2026.acl-long.609/) 还显示，多轮长文修订即使解决了用户反馈，也会使 16%–27% 先前已覆盖内容或引用质量退化，专用修订 Agent 也不容易修好。[B，间接反证]

所以 critic 的正确位置是：

- 程序先检测到明确风险，例如 patch 移除不存在物品、NPC 使用未知信息、时间倒退、玩家行为被代写；
- critic 只阅读冲突证据、相关状态和一个很小的文本片段；
- 输出“是否冲突、冲突证据、允许的最小修复范围”，而不是自由评论全文；
- 优先修 patch 或冲突句，保留已经流式展示的其余正文；
- 每次修复必须跑原事实与选项/格式回归，不能因修一个问题引入新的丢失。

## 6. “更戏剧化”不等于更好玩，尤其不等于当前项目需要的风格

不少互动戏剧论文天然以预定义剧本、秘密、冲突、悬念和情绪张力为目标。[Enhanced Immersion and Agency](https://aclanthology.org/2025.acl-long.546/) 的剧作引导甚至刻意提高 suspense 和 emotional tension。对侦探剧这是成功，对用户想玩的日常、经营、轻喜剧、友情、退队后生活或自由修行则可能正是“悬疑剧味”“中二用力过猛”的来源。

因此网文/日轻标签数据库的正确用途不是把每个标签扩成硬提示词，而是生成**场景 affordance（可发生的事情）**：

- `退队流` 可以产生公开评价变化、旧队友关系、职业机会，不必产生幕后阴谋；
- `挚友流` 可以把主线驱动力放在共同生活、承诺与互相支持，不要求主角成为天命中心；
- `异种转生` 影响身体 affordance、感知、社会反应和资源需求，不自动决定正邪与升级路线；
- `乙女/百合游戏穿越` 只提供社交结构、原作知识边界和可偏离角色关系，不要求攻略固定角色或复刻原作结局；
- 仙侠、武侠、赛博、末日等世界包提供规则与机会，不预定“惊天阴谋”。

压力、悬疑、战斗、恋爱、经营都应是当前场景的可调预算，而不是全局铁律。

## 7. 如何评价“真的变好”

[OpenMEVA](https://aclanthology.org/2021.acl-long.500/) 显示自动指标与人评相关较弱，常漏掉篇章不连贯和事件因果顺序；[HANNA](https://aclanthology.org/2022.coling-1.509/) 在 1,056 个故事、10 个系统和 72 个指标上同样说明没有一个自动分数可代替多维人评。[A]

[Illusions of the Gold Standard](https://aclanthology.org/2026.acl-long.635/) 对 284 篇论文的人工复核发现，长篇生成人评普遍漏报任务定义、评价者、流程和分析细节；“有人评”本身也不等于可靠。[A]

本项目不需要论文级实验，但需要可复现的产品验收：

### 固定多回合存档集

1. **承诺召回**：NPC 在 20 回合前答应某事，到期时能直接回应。
2. **知识边界**：A 私下得知的事，B 不得无来源知道。
3. **拒绝保留**：玩家拒绝入口后，不得换名重发同一入口。
4. **玩家因果足迹**：同一存档的两个玩家选择导致至少一个可观察后续差异。
5. **人物动态**：短期生气可恢复，不应把稳定身份写崩。
6. **类型/基调**：低压力日常 5 回合内不得自动升级为阴谋或追杀。
7. **相关性**：每段描述能说明服务于行动、空间、关系或信息中的哪一项。
8. **既有 UX**：世界观/供应商/主界面/存档/长文本/SSE/回车/行动选项全部保留。

### 指标

- 硬错误：事实、时间、物品、人物知识、玩家越权、拒绝失效，每类计数；
- 体验维度：连贯、相关、有趣、人物可信、玩家影响、节奏，各自 1–5 分；
- 系统代价：首 token 延迟、总回合时间、模型调用数、输入/输出 token、重试数；
- 对照：同一模型、温度、世界、存档和玩家输入，随机隐藏 A/B 版本；
- LLM 裁判只做预筛，最终版本判断由真人盲评和硬规则结果共同决定。

## 证据无法支持的主张

- 没有证据证明多 Agent 数量越多，连续游戏越好。
- 没有证据证明把完整小说类型学塞进 system prompt 能稳定提高体验。
- 没有证据证明长上下文可以替代长期记忆和状态。
- 没有证据证明 LLM 自我反思可以可靠发现细微人设冲突。
- 没有证据证明离线故事的“情节完整”会自动转化为玩家能动性。
- 没有证据证明任何一篇论文的方法能跨全部 18 个世界包、不同供应商和任意自由输入直接成立。

## 最终综合

### 可以进入推荐架构

- 分层、动态、短视窗规划；
- 正史/事件/人物知识/承诺/动态心理的结构化分层；
- 时间、来源和角色可知性优先于语义相似的检索；
- 普通场景单写手、高风险场景选择性导演；
- 硬规则先行、证据定位后的局部 critic；
- 固定多回合 A/B 和人工盲评。

### 只进入实验候选

- 多批评者讨论创造性；
- 每 NPC 独立角色 Agent；
- 自动整段重写；
- 大规模时间知识图和向量数据库；
- 依赖单一 LLM judge 的自动质量闸门。

具体落地顺序和与当前代码的映射见 `interactive_narrative_architecture_decision.md`。
