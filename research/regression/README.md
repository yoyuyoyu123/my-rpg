# Phase 0：叙事回归基线

本目录先定义“怎样才算真的变好”，不改变生成架构。

## 当前已完成

- `phase0_scenarios.json` 固定八类验收场景和主要指标。
- `tools/analyze-debug-trace.mjs` 可直接读取前端导出的 `myrpg_*_debug_*.json`，使用当前生产代码里的诊断器和行动选项解析器重新计算结果。
- 诊断器兼容旧普通模式和新剧情规划模式的迁移约束标题，避免把有效提示误报为严重缺失。
- `fixtures/narrative_diagnostic_cases.json` 提供拒绝持续与低压力基调的脱敏正反例；`tools/test-narrative-diagnostics.mjs` 直接执行生产诊断代码。

## 使用

```powershell
node tools\analyze-debug-trace.mjs "C:\Users\你的名字\Downloads\myrpg_debug.json"
```

报告目前能确定性统计：回合状态、生成耗时、正文长度、行动选项、玩家主权违规、调试警报和迁移前提缺失。

当前拒绝/基调诊断边界：

- 拒绝入口后正常日常事件或另一条客观路线不会告警；同一个确认框、按钮、邀请或入口再次出现才告警。
- “神秘口味”等单纯修辞不会被算成升压；需要悬疑信号与威胁/谜语人信号共同出现，或多项威胁同时出现。
- 玩家主动追查、潜入或迎战时不算“无铺垫升级”；玩家说“不要调查/离开危险”仍然是拒绝，不能放开危机。

承诺生命周期、NPC知识来源、分支因果差异和中短期人格状态还没有结构化数据，因此明确标为 `notYetMeasurable`，不能用关键词分数假装已经解决。它们将在 Phase 1 随数据库字段逐项接入。

## 数据安全

真实调试导出包含完整玩家输入、模型正文、提示词和游戏状态，不提交进仓库。只提交脱敏的最小测试夹具。
