# 无界 2.0 产品定义

状态：草案 v0.1（2026-10-28）  
作用：这份文档是**过滤器**。任何新功能、新规则、新 Agent，先回答"它服务于下面哪一条"，答不上来就进[点子停车场](#7-点子停车场)，不进代码。

---

## 1. 一句话愿景

> **一个本地运行的中文 AI 互动小说 / 文字 RPG：玩家用自然语言在一个世界里长期生活和冒险，玩到的是靠得住的游戏，在世界事实之内做决定的永远是玩家自己，读到的是像样的小说。**

参照形态（用户原话，2026-10-28）："**AI 作为 DM 的类 DnD 游戏，只不过叙事可以更丰富（丰富得像小说）**"。研究与跑团经验见 [RESEARCH_AI_DM.md](./RESEARCH_AI_DM.md)。

## 2. 为谁做、为什么做

| 对象 | 他们要什么 | 对设计的含义 |
|---|---|---|
| **我自己（主要玩家）** | 好玩、不出戏、主线不丢 | 体验问题优先于工程洁癖；所有改动以"玩起来是否更好"为最终验收 |
| **读代码的人（作品集）** | 看出作者懂 LLM 应用工程 | 架构边界清晰；每个 Agent 职责可说清；叙事质量**可评测**而非靠感觉；有架构文档和设计决策记录 |

不面向：陌生公众用户。不承担公开支持、问题模板、兼容各种环境的义务。

## 3. 核心体验：三支柱及冲突时的优先级

沿用 1.x 的三支柱，2.0 明确它们**冲突时谁让步**（2026-10-28 确定）：

1. **游戏可靠性**（最高）——钱、背包、位置、时间、关系、承诺、NPC 各自知道什么，由程序记账，模型只能申报不能直接改。主线和已确立的设定不会被遗忘。**已确立的事实谁都不能靠一句话改写，包括玩家。**
2. **玩家主权**——在世界事实之内，决定永远由玩家做：玩家输入是"尝试"，不是既成结果；系统不替玩家说话、不替玩家接受/拒绝、不跳过玩家该做的决定。
3. **小说体验**——正文自然、有生活感、详略得当、流式即时出现。

冲突例子：

| 冲突 | 谁赢 | 表现 |
|---|---|---|
| 玩家写"我掏出一万两银票"，账本只有三两 | 可靠性（1 > 2） | 当作一次尝试：摸遍全身只有三两碎银，而不是凭空多出钱 |
| 模型写出精彩但与账本矛盾的段落 | 可靠性（1 > 3） | 段落不生效，状态以账本为准 |
| 剧情规划想推进主线，玩家拒绝 | 玩家（2 > 3） | 主线换个方式等待或另找入口，不强推 |

## 4. 核心循环

### 4.1 一回合

```text
玩家输入（自由文本 / 选项）
  → 理解意图与风险（是否需要检定）
  → 程序裁定可程序化的部分（检定、交易、移动）
  → 写手根据"本幕要写什么 + 公开可见的事实"写正文（流式）
  → 结算状态变化（程序校验后生效）
  → 记住发生了什么（事件、承诺、谁知道了什么）
```

每回合是一个**可整体撤销**的单位：要么全部生效，要么全部不生效。

### 4.2 一局的两种形态（都要支持）

| 形态 | 长度 | 关键需求 |
|---|---|---|
| **长篇连载** | 几百回合、跨多天 | 主线和人物关系不丢；记忆可检索、可追溯；存档稳定、可迁移 |
| **中篇有结局** | 一两个晚上 | 开局就有故事骨架（目标/冲突/可能结局）；节奏推进到结局；能结束并留档 |

两者共用同一套回合循环；差别只在"剧情规划的尺度"和"是否设定终点"，不做两套引擎。

**中篇的结局怎么来**（2026-10-28 确定）：规划器在开局时定下 2–4 个候选结局，玩家看不到；玩家的选择决定故事走向哪一个。这样伏笔从第一章就能埋，故事也有边界。候选结局是规划器的私有数据，与玩家主权不冲突——它限定的是"可能的终点"，不替玩家做任何一步决定。若玩家的行动把故事带离所有候选，规划器修订候选，而不是把玩家拉回去。

### 4.3 一局的起点

选择内置世界或自定义世界 → 设定/随机身份与开局 → 第一章。世界与开局的**多样性**来自研究数据库的随机组合，而不是在提示词里堆规则。

**开局约定即授权**（2026-10-28 确定，参照跑团 Session Zero）：玩家在开局选定的前提（例如"会穿越到异世界"）就是对系统的授权，系统应主动推进它发生，不受"不强推剧情"的约束；玩家在前提之后的每一个具体行动仍由玩家决定。前提以带触发条件和期限的数据记录保存，而不是写进提示词。

## 5. 运行形态与技术边界

- **桌面应用**：打包后双击即用，内含本地后端；不需要用户装 Python、开终端。手机通过同一局域网访问是可选能力，不是主路径。
- **模型**：以云端大模型（DeepSeek 级别及以上）为质量基准；兼容 OpenAI 格式的接口均可接入。本地小模型"能跑"，但不保证体验，也不为它牺牲设计。
- **语言**：中文。界面文案不写死在代码里，为将来加日/英留出口子，但 2.0 不做翻译。
- **数据**：全部在本机。API Key 只存本机。用户数据（存档、设置）与内置内容（世界、研究库、提示词模板）物理分开存放。

## 6. 非目标（2.0 不做）

| 不做 | 理由 / 将来可能的去向 |
|---|---|
| 模组 / 插件系统 | 先把核心做对。但数据格式要留未知字段的位置，不堵死将来 |
| SillyTavern 角色卡 / 世界书导入 | 将来作为模组实现，核心不内置 |
| 多人联机、账户系统、网页托管 | 本地单人游戏 |
| 本地小模型的质量保证 | 见第 5 节 |
| 多语言翻译 | 只留 i18n 出口 |
| 复杂战斗 / 地图 / 经济模拟 | 除非先证明它服务于三支柱，并有固定回放场景 |
| 每个 NPC 一个常驻 Agent | 成本与复杂度不成比例 |
| 语音朗读、图片生成 | 与核心体验无关 |

## 7. 点子停车场

"觉得好玩就想加"的点子不丢，也不直接进代码：

1. 写进 `docs/v2/IDEAS.md`，一行一个，写清**它解决什么玩起来不顺的问题**。
2. 只有当它能对应到第 3 节某根支柱的一个**已观察到的问题**（最好有一局存档或回放为证）时，才升级为需求。
3. 升级前先问：能不能用数据或现有机制解决，而不是加一条常驻规则？

## 8. 从 1.x 带进来的设计原则

这些是 1.x 用真实试玩换来的教训，2.0 默认遵守：

- **规则越多叙事越差。** 每条常驻提示词规则都会变成模型每轮要完成的 KPI（1.x 出现过"全员侦探、万物皆线索"）。情境性要求由规划/裁定按回合下达，写手的常驻规则保持极少。
- **一个决策只有一个权威。** 1.x 末期 142 条提示词规则里，"本幕何时停""穿越阶段推进"等决策被 3–4 个 Agent 共管，互相打架。2.0 的每个决策域只能有一个负责方。
- **写死的提示词必然雷同。** 多样性来自大库存数据 + 每局随机抽样，而不是更多的描述。
- **能程序化的不交给模型。** 检定、交易、背包、承诺状态由程序结算；模型负责语言和判断。
- **70% 的 NPC 没有秘密。** 生活感与反谄媚要配平，避免谜语人。

## 9. 从 1.x 保留的资产

- 中日作品研究数据库（标签本体 + 证据分层 + 来源）
- 程序权威的角色状态与结算规则
- 按时间/来源/NPC 知情范围组织的叙事账本
- 10 个世界的目录与世界内容
- 回放测试场景、质量指标的思路

保留的是**设计与数据**，代码按 2.0 架构重写或迁移，不默认照搬。

## 10. 成功标准（待定量）

2.0 算"做成了"的验收，必须能测。1.x 基线见 [BASELINE_1X.md](./BASELINE_1X.md)。"建议门槛"一列待确认。

| 支柱 | 指标 | 1.x 基线 | 建议门槛（待确认） |
|---|---|---|---|
| 游戏可靠性 | 长局回放中账本与正文矛盾次数 | 不可测 | 先建测量；固定回放中为 0 |
| 游戏可靠性 | 第 100 回合仍能召回第 1 章主线 | 不可测（最长数据 24 回合） | 先建 100 回合长局回放；固定问题全部答对 |
| 玩家主权 | 写手疑似替玩家决定的比例（守卫触发率） | 约 5% | ≤ 2%；守卫改写后残留为 0 |
| 小说体验 | 节奏与故事意图是否一致（该紧张时紧张、该日常时日常） | 不可测：1.x 没有可对照的意图数据 | 先建"故事意图"模型再定。无冲突幕数只作观察项，不设全局门槛——有没有冲突要看大纲 |
| 小说体验 | 回合有 2–4 个有效行动选项 | 约 90%，首回合常缺 | ≥ 98%，首回合必有 |
| 小说体验 | 谜语人率 / 因果桥缺失 | 恒为 0（指标未证明能报警） | 先证明指标有效再定 |
| 性能 | 回合耗时 | 中位 9.3 s，P90 21.4 s | 中位 ≤ 10 s，P90 ≤ 20 s |
| 工程 | 被多方共管的决策域 | 10 / 10 | 0 |
| 工程 | 新人（或一年后的我）说清一个回合经过哪些模块 | 回合编排在 1 MB 前端里 | 30 分钟内 |
| 可用性 | 从下载到开玩第一局 | 需先自装 Python，约 5 步 | 不需要装任何依赖，≤ 3 步 |
