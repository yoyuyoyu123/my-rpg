## 1. 为什么要 2.0

1.x 是"觉得好玩就加"长出来的，没有需求，只有感觉。复盘（[RETRO_1X.md](./RETRO_1X.md)）的核心结论：

- 【事实】能程序化的部分（状态、检定、账本）做得不错，确定性回放 10/10。
- 【事实】叙事问题反复返工：提示词规则涨到 142 条，规则清点工具列出的 10 个决策域**全部**被多方共管；两条规则互相矛盾时"只有模型违抗指令时才会前进"（33b9f6c）。
- 【事实】最高优先级的可靠性在 1.x 基本**不可测**：没有账本矛盾检测，现有对局最长只有 24 回合。
- 【判断】根因有三：
  1. 用提示词对抗模型的天生倾向（谄媚、雷同、替主角抒情）；
  2. 用全局规则去猜本该由每局意图决定的事（节奏、冲突）；
  3. 互相矛盾的目标没有在产品层定优先级。

## 2. 产品设想（摘要）

完整版见 [PRODUCT.md](./PRODUCT.md)。

> 一个本地运行的中文 AI 互动小说 / 文字 RPG：玩家用自然语言在一个世界里长期生活和冒险，玩到的是靠得住的游戏，在世界事实之内做决定的永远是玩家自己，读到的是像样的小说。

- **参照形态**：AI 当 DM 的类 DnD 游戏，叙事丰富得像小说【已定 D014】。
- **对象**：自己玩为主，兼做作品集【D002】。
- **三支柱优先级**：游戏可靠性 > 玩家主权 > 小说体验【D010】。
- **一局的形态**：长篇连载与中篇有结局都要，共用一套引擎【D004】。中篇在开局定 2–4 个隐藏候选结局【D011】。
- **开局约定即授权**：玩家在开局选定的前提（如穿越），系统主动推进；前提之后的每个具体行动仍由玩家决定【D015】。
- **运行形态**：桌面应用【D005】，以云端大模型为质量基准【D008】，中文为主并留 i18n 出口【D009】。
- **2.0 不做**：模组系统【D006】、SillyTavern 卡导入（将来做成模组）【D007】、联机、本地小模型质量保证、翻译、复杂战斗与地图模拟、语音和图片。
- **点子停车场**：新点子先进 `IDEAS.md`，必须对应一个**实际试玩中观察到的问题**才升级为需求。

## 3. 核心架构设想

### 3.1 总体：三层加账本

```text
                 ┌──────────────────────────────────────────────┐
 开局约定 ──────▶│ 结构层  故事意图（全部是数据，由程序控制）   │
 (Session Zero)  │  前提承诺 / 威胁阵线与凶兆 / 进度钟 /        │
                 │  揭示与线索 / 秘密池 / 候选结局 / 目标张力曲线│
                 └───────────────┬──────────────────────────────┘
                                 │ 本幕预算
 玩家宣告行动 ──▶┌───────────────▼──────────────────────────────┐
                 │ 事件层  GM（LLM 提议）+ 程序裁定与校验        │
                 │  局势与效果 → 掷骰 → GM 行动（软/硬）→ 事件   │
                 └───────────────┬──────────────────────────────┘
                                 │ 已确定的结构化事件
                 ┌───────────────▼──────────────────────────────┐
                 │ 文字层  写手（LLM）把事件写成小说级正文       │
                 └───────────────┬──────────────────────────────┘
                                 ▼
                 账本（程序）：状态 / 事实 / 事件 / 承诺 / NPC 认知
```

**设计原则**：

1. **LLM 只能提议，程序决定。** 凡是能程序化的裁定，都不交给 LLM（证据：CoC 裁判研究，玩家话术能绕过 22 个模型的规则判断）。
2. **结构不写进提示词。** 结构以数据形式存在，由程序推进；写手只收到"本幕要写的事件和预算"。
3. **一个决策域只有一个负责方**（见 §3.6）。
4. **随机性留在程序侧**：起名、秘密、势力、事件类型从外部分布抽样。

### 3.2 开局约定（Session Zero）

开局问答的产物都是数据，不写成提示词：
- 前提承诺：带触发条件和期限；
- 基调与节奏偏好：生成目标张力曲线；
- 界限（lines）与淡化处理（veils）；
- 中篇的隐藏候选结局；
- 初始的威胁阵线、势力局势和秘密池。

### 3.3 结构层：故事意图与形式化

两层规划（来自 1.x 综述 §1，与 RESEARCH_AI_DM 一致）：
- **长期层**：威胁阵线与凶兆、前提承诺、人物目标、候选结局、期待债。
- **眼前层**：2–4 回合有效的本幕预算，包括张力目标、详略、可揭示信息、可用的 GM 行动。

跑团经验直接编码成数据（出处见 RESEARCH_AI_DM §2）：

| 结构 | 数据形态 |
|---|---|
| 进度钟（Blades in the Dark） | `Clock{name, size, filled, on_full}`，势力钟按回合推进 |
| 威胁阵线与凶兆（Dungeon World） | 有序凶兆列表；久未推进则报警，用来防主线丢失 |
| 三线索规则（Alexandrian） | `Revelation{clues≥3, delivered[]}`；N 回合未揭示就安排一个主动送上门的线索事件 |
| 秘密池（Lazy DM） | 约 10 条不绑定具体场景的秘密，合适时投放 |
| 局势而非剧情（Alexandrian） | 每个势力一条记录：目标、资源、时间线 |

形式化的量（均为【假设】，见 H08–H10）：
- **认知差**：NPC 以为的主角实力与真实实力之差。打脸、扮猪吃虎的爽感大致正比于"认知差 × 围观规模"，可以直接从 `NpcBelief` 账本算出。
- **期待债**：每条伏笔、每个承诺记为一笔债，带上已过时长。期待感 = 未清偿债务的加权和；爽点 = 一次清偿。
- **悬念与惊奇**：用 Ely, Frankel & Kamenica (2015) 的定义安排信息揭示的时机。悬念是读者对结局的判断在下一步可能变化多大，惊奇是判断实际变化了多少。
- **张力曲线跟踪**：规划器选下一场戏时，让实际张力贴近本局的目标曲线，并保留一点随机性防止套路化。"有没有冲突"因此变成"离目标曲线差多少"【已定 D013】。
- **场景转移统计**：对小说做逐章结构标注（场景类型、张力、伏笔、兑现），学出场景之间的转移分布。只存抽象标签，不存原文。

### 3.4 事件层：AI DM

每回合：

1. 玩家宣告行动。
2. 程序理解意图，确定局势与效果（position & effect），然后掷骰。
3. GM（LLM）从**封闭的行动清单**中提议 GM 行动，分软行动和硬行动；玩家无视软行动时才升级为硬行动；行动名称对玩家隐藏。
4. 程序校验提议，三项硬规则：
   - 事件里**没有"玩家角色的行动或感受"这个字段**；
   - 不得违反账本；
   - 检定失败必须带来复杂化，或推进一格进度钟（fail forward）。
5. 通过校验的事件交给文字层。

### 3.5 文字层：写手

写手收到的是一份工作说明，而不是规则清单：本幕事件、本幕预算、选定的 1–2 张写作技法卡、可公开的事实，最后以"你怎么做？"收尾。

可能提升"小说感"的手段，按成本从低到高：

1. **写作技法卡**：从网文技法整理一份封闭清单（打脸、扮猪吃虎、日常温情、悬念收尾……），由规划器按场景挑选，并与研究库的题材标签关联（H04）。
2. **局部修订 AI 味**：程序检测抽象情绪词、总结句和高频套话，只让模型改被标出的句子（H05）。
3. **写手模型单独选型**：规划和裁定可以用便宜的模型（H06）。
4. **范文参考**：只用本机、不进仓库的参考文本，或只提炼技法不放原文（有版权约束）。
5. **炼网文**：用"事件卡 → 正文"配对数据做 LoRA 微调，数据靠指令回译从好的正文里反向提炼事件卡；数据只用公版作品、自写文字和合规的合成数据（H07）。

已知的真实冲突：网文的代入感很多来自主角的内心活动，但主权规则禁止替玩家写主角的感受。候选解法是写他人对主角的反应、写世界的变化，主角内心只写玩家自己表达过的【待决 Q3】。

### 3.6 决策权威表（草案）

1.x 的 10 个共管决策域，在 2.0 里各归一个负责方：

| 决策 | 1.x | 2.0 负责方 |
|---|---|---|
| 本幕何时停 | GM / 写手 / 规划器 | 结构层（本幕预算） |
| 本幕写多长 | 写手 / 规划器 | 结构层（详略预算） |
| 谁决定玩家的行动 | 三方 | 玩家；事件层结构上禁止 |
| 能不能引入新事件 | 写手 / 规划器 | 事件层（GM 行动清单 + 程序校验） |
| 强度与冲突 | 四方 | 结构层（张力曲线 + 进度钟） |
| 前提阶段推进 | 三方 | 结构层（前提承诺数据）【D015】 |
| 专名怎么起 | 写手 / 规划器 | 程序抽样 |
| NPC 知道什么 | 多方 | 账本（NPC 认知） |
| 状态怎么改 | 多方 | 程序（只接受事件导致的变化） |
| 行动选项 | 多方 | 事件层产出候选，文字层只负责措辞 |

### 3.7 账本（沿用 1.x 设计）

事实（正史）、事件、承诺 / 拒绝、NPC 认知、人物动态状态、角色数值。保留的是设计和数据，代码按 2.0 重写或迁移。

## 6. 风险

- **文字层仍是最大的未知**：结构和事件都对了，正文照样可能有 AI 味。
- **事件化可能让叙事变僵**（H12）。
- **单一玩家，样本小**：盲评和反馈需要很多局才有说服力。
- **公式化导致套路化**：网文读者要的是熟悉套路里的意外。
- **成本与延迟**：1.x 已是每回合 2.63 次调用、中位 9.3 秒；新增的每一步都要说明换来了什么。
- **范围蔓延**：这正是 1.x 的病。新想法一律先进点子停车场。
- **版权**：训练数据与范文。

## 7. 计划

原则：**先建尺子，再造东西**。1.x 的教训是"玩家在充当测试环境"。每个新模块先写设计文档（候选比较 + 计划），再动手。按稳定节奏一步步推进，不提前铺开后续阶段。

| 阶段 | 目标 | 产物 | 出口条件 |
|---|---|---|---|
| **A 定义与基线** | 知道要做什么、现在在哪 | v1-final；PRODUCT、BASELINE、RETRO、RESEARCH、DECISIONS、本文件 | 文档已提交；Q1 已决 |
| **B 测量设施** | 能判断"变好了没有" | ① 写手实验台（固定场景 × 多种配置，你两两盲选）；② 长局回放与账本矛盾检测；③ 验证"谜语人""因果桥"两个指标能否报警；④ 每章反馈的格式 | 实验台能出偏好统计；长局回放跑通 100 回合 |
| **C 调研** | 文字层与结构层的依据 | 网文写作技法（中文来源）；LLM 创意写作与去 AI 味研究；结构标注方案 | 技法卡初版；标注规范 |
| **D 纵切原型** | 验证三层架构 | 最小回合链：开局约定 → 意图数据 → 事件层 → 写手 → 账本，先只做一个世界 | 与 v1-final 对比验证 H01、H02、H12 |
| **E 写手专项** | 解决小说感 | 技法卡、局部修订、模型选型；如有必要，搭炼网文流程 | H04–H07 有结论 |
| **F 结构模型** | 形式化节奏与爽感 | 结构标注语料、转移统计、认知差与期待债模型 | H08–H10 有结论 |
| **G 产品化** | 能装、能玩、能长期用 | 桌面打包、世界与研究库迁移、界面、存档迁移 | §10 门槛达标 |

B 和 C 可以并行；D 依赖 B；E、F 依赖 D 的接口；G 最后做。

## 8. 从 1.x 继承

- **数据**：中日作品研究库（551 部，标签本体、证据分层、来源）、10 个世界的目录与内容、回放夹具、质量指标思路。
- **设计**：程序权威的状态与结算、叙事账本（按时间、来源和 NPC 知情范围组织）、两层规划、确定性回放。
- **教训**（PRODUCT §8）：规则越多叙事越差；一个决策只有一个负责方；写死的提示词必然雷同；能程序化的不交给模型；70% 的 NPC 没有秘密。
