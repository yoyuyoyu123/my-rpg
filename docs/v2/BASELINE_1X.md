## 一、按三支柱

### 1. 游戏可靠性

| 指标 | 1.x 基线 | 说明 |
|---|---|---|
| 账本与正文矛盾次数 | **不可测** | 现有评分器没有这个指标 |
| 第 N 回合仍能召回第 1 章主线 | **不可测** | 没有超过 24 回合的数据 |
| 记忆召回带纳入理由的比例 | 95–100%（13 局） | 只说明召回"可解释"，不说明召回得"对" |
| 确定性协议回放 | 10/10 通过 | 状态结算、存档、分叉在假模型下稳定 |

**结论：可靠性这根最高优先级的支柱，1.x 几乎没有真实对局层面的测量。** 2.0 必须先补测量手段（长局回放 + 账本矛盾检测），否则 §10 的可靠性门槛无从验收。

### 2. 玩家主权

| 指标 | 1.x 基线 | 说明 |
|---|---|---|
| 主权守卫触发改写 | 10 次 / 201 回合（约 5%） | 写手每 20 回合左右产出一次被判为"替玩家决定"的正文，由守卫改写后才展示。守卫本身有误判记录（commit 7d350cb），所以这是"疑似违规率"的上界 |
| 改写后仍残留的违规 | **不可测** | 没有独立于守卫的检测 |

### 3. 小说体验

| 指标 | 1.x 基线 | 说明 |
|---|---|---|
| 无冲突幕占比 | **75 / 81 幕（93%）** | 13 局里 11 局触发"走马观花"（连续 ≥3 幕无冲突），最长连续 11 幕。**这是观察值，不是缺陷率**：日常向故事本该多数幕无冲突，是否偏离要对照该局的故事意图，而 1.x 没有记录意图 |
| 穿越类开局的转移 | 5 局在 9–22 回合内始终未落地；1 局阈限到落地用了 17 回合 | 与玩家原话"推进依然慢得要死""依然不穿越"一致 |
| 正文长度（中位） | 492 字符 / 回合 | |
| 行动选项完整度（2–4 个有效选项） | 181 / 202 回合（约 90%） | 缺失集中在**开局第一回合**：13 局中 7 局首回合 0 个选项 |
| 谜语人回避信号 | 0%（13 局全部为 0） | 见下方"指标本身的问题" |
| 因果桥缺失率 | 0%（13 局全部为 0） | 同上 |
| 场景目的重复 | 13 局中 2 局 ≥3 次（3 次、4 次） | |

**指标本身的可信度**：`score_session.py --validate` 对照玩家原话，6 局中命中 5 局、漏报 1 局（中式地名出现在西式世界）。但"谜语人"和"因果桥"两项在 13 局里全是 0——要么 1.x 确实没有这两个问题，要么指标区分不出来。在有一局"已知有问题"的对局能让它们报警之前，**不能把这两个 0 当作达标**。

## 四、可用性

从零开始玩到第一局：先自行安装 Python 3 → 双击 `启动无界.vbs` → Install / Repair → API Settings 填 Key → Start and Play。**前置要求是会装 Python**，这对"打包成桌面应用"的目标是硬缺口。

## 五、对 2.0 的直接含义

1. **节奏无法被评价，因为没有可对照的意图。** 93% 的幕无冲突，且这些局里玩家说过"非常之无聊"；但"有没有冲突"本身不是好坏标准（见 `research/interactive_narrative_systematic_review.md` §6：压力与冲突应是场景预算，不是全局铁律）。问题在于 1.x 没有记录"这个故事此刻想要什么"，所以既无法让写手对准，也无法事后判断偏了没有。
2. **最高优先级支柱（可靠性）在 1.x 基本不可测**，长篇连载零数据。2.0 第一批工作里必须有"长局回放 + 账本矛盾检测"。
3. 两个恒为 0 的叙事指标需要先证明能报警，才能用作门槛。
4. 本次样本是穿越调试期的对局，偏向开局问题。若要更公平的基线，需要在 v1-final 上补几局日常游玩（含非武侠世界、30 回合以上）——这需要真实调用模型，有 API 费用。

## 复算方法

```bash
# 确定性回放
backend/.venv/Scripts/python.exe tools/run_replay.py --fixture research/regression/fixtures/replay_baseline.json
# 逐局指标（导出目录先按内容去重）
backend/.venv/Scripts/python.exe tools/score_session.py --dir <导出目录>
backend/.venv/Scripts/python.exe tools/score_session.py --validate --dir <导出目录>
# 规则清点
backend/.venv/Scripts/python.exe tools/rule_inventory.py
```

性能、调用次数和 token 由一次性脚本按运行 ID 去重后汇总监视器导出的 `durationMs`、`agent`、`usage` 字段得到；该脚本未进仓库，2.0 应把它做成正式工具。
