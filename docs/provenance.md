# 文档与溯源规则

这套规则适用于代码、数据、体验与调查。按信息的重要程度记录，不要求每次小修改另建文档。

## 当前信息放在哪里

| 信息 | 当前正本 | 历史或依据 |
|---|---|---|
| 目的与启动 | README.md；后端细节见 backend/README.md | 入口代码、配置 |
| 当前能力、缺口与下一步 | STATUS.md | progress.md、验证记录 |
| 模块职责与数据流 | docs/architecture.md | 对应代码 |
| 设计决定与约束 | docs/decisions.md | 用户指示、讨论记录、代码或调查 |
| 研究数据语义与构建 | research/DATABASE_GUIDE.md | 源 JSON、本体、crosswalk、审计记录 |
| 外部资料支持范围 | 对应研究记录及其源数据 | 原始 URL、核对日期与具体证据 |

代码、执行结果与文档冲突时，先确认版本和环境；保留差异，修正当前说明。历史文档不能替代当前验证。

## 一条重要结论应留下什么

- **结论与性质**：事实、推断、建议或待确认。
- **来源**：文件路径与适用提交，或原始 URL；涉及用户决定时记录原始指示的出处。
- **核对日期**：记录实际核对时间。旧资料今天整理，不等于今天重新验证。
- **支持范围**：来源能证明什么，不能证明什么。
- **验证**：命令、环境、结果和限制；未执行就明确写未执行。

例如：2026-10-08 阅读 tools/embed_research_db.mjs，确认其目标为 wuji_v25_reviewed.html。这能证明脚本写入路径，不能证明两份页面数据不同，也不能证明页面运行正常。

## 研究与生成物

沿用 DATABASE_GUIDE 的证据等级，不把等级当作品质量或销量评分。来源证明作品获奖，不自动证明对它的所有叙事标签分析。记录人工分析与直接来源事实的差别。

更新数据保留源记录 → 映射/本体 → 构建脚本 → 生成物的关系。统计必须注明快照与口径；2026 YTD 不能写成完整年度。

## 验证与工作记录

progress.md 保留历史追加记录。较大验证可放 docs/validation/YYYY-MM-DD-主题.md，至少包含代码版本、环境、步骤、结果、未覆盖部分；有这样的记录再建立文件，不预先创建空档案。

功能实现、自动测试、浏览器操作、真实模型体验分别陈述。旧“161 项通过”只能作为历史报告引用，不能作为本轮通过证据。
