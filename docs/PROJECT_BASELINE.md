# 无界项目基线

版本基线：2026-08-22  
产品：本地 AI 互动小说 / 文字 RPG  ���
运行形态：Windows 本地 FastAPI 服务 + 浏览器前端；GitHub Pages 只能承载静态壳，不能作为完整版后端。

## 1. 产品定义

玩家在一个可选择或自定义的世界中，通过自然语言和行动选项进行长期游玩。系统需要同时满足三件事：

1. **小说体验**：正文自然、足够长、能流式出现，人物和世界有生活感。
2. **游戏可靠性**：钱、背包、任务、位置、关系、时间和承诺不能靠模型临场记忆。
3. **玩家主权**：玩家输入是尝试，不是既成结果；系统不能替玩家接受任务、替玩家说话或强行跳过关键决定。

## 2. 产品边界

### 属于本项目

- 世界观选择、自定义世界、预设和研究标签组合。
- 开局身份/关系/成长方向的生成和保存。
- 长篇自然语言回合、行动选项、自由输入、SSE 流式输出。
- 状态、存档、回滚、事实、事件、承诺、NPC 知识和人物动态状态。
- 条件触发的剧情规划、GM/规则裁定、状态审计和后台事实抽取。
- 本地 API 配置、启动器、后台 Agent 监视器和调试导出。

### 暂不属于本阶段

- 多人联机和服务端账户系统。
- 把所有类型研究标签直接注入每回合提示词。
- 每个 NPC 一个常驻 Agent、常开多 Agent 会议或全文自动重写。
- 复杂战斗/地图/经济模拟，除非先有明确玩法需求和固定回归场景。
- 把 GitHub Pages 当作可以安全保存 API Key 或运行 SQLite 的生产后端。

## 3. 当前运行链路

```text
用户打开启动器
  -> 启动本地 FastAPI
  -> 浏览器加载 index.html
  -> 读取世界包、设置、存档和后端状态

新局/回合
  -> 前端收集玩家输入与当前运行时快照
  -> 后端检索结构化记忆
  -> 必要时生成/刷新 SceneContract
  -> 后端编译场景写手提示词
  -> 通过 /api/chat/stream 代理模型 SSE
  -> 前端即时显示正文
  -> 解析行动选项、状态 patch 和调试信息
  -> 程序校验并应用状态
  -> 写入存档、事件账本和异步事实抽取
```

## 4. 当前组件盘点

| 组件 | 当前实现 | 当前职责 | 主要风险 |
|---|---|---|---|
| `index.html` | 约 1 MB 单文件 HTML/CSS/JS | UI、开局、回合编排、SSE、选项、存档、监视器 | 变更边界模糊，前端仍拥有大量领域逻辑 |
| `backend/app/domain/` | Python 领域常量 | 世界包、供应商、规则、研究标签 | 世界设定与前端历史资产存在双份来源 |
| `backend/app/routers/` | FastAPI 路由 | API 收发、权限/错误转换 | 需保持不包含业务逻辑 |
| `backend/app/services/` | Python 服务 | LLM、提示词、规划、记忆、状态、抽取 | `turn` 主流程仍分散在前端和后端 |
| `backend/app/schemas/` | Pydantic | API 和 Agent 结构化契约 | 需要版本化、错误码和迁移策略 |
| `backend/app/db/` | SQLAlchemy + SQLite | 会话、存档、实体、事实、事件、承诺、NPC知识、人物状态 | 尚缺正式迁移工具和完整生命周期约束 |
| `research/` | JSON/Markdown/CSV | 中日网文、轻小说、漫画标签研究 | 研究库与运行时组合之间缺少稳定查询接口 |
| `tools/` | Node 脚本 | 构建研究库、静态契约、调试分析 | 缺统一命令入口和测试分层 |
| `launcher.ps1`/VBS | Windows 启动器 | 安装、启动、停止、设置、日志 | 需要独立的启动器回归和版本策略 |

## 5. 权威性分层

### 程序权威

- 玩家当前状态：HP、资源、背包、技能、装备、位置、时间。
- 已确认的世界/玩家设定。
- 事件顺序、承诺状态、NPC 各自知识边界。
- 存档版本、回合号、幂等键和回滚快照。

### Agent 可提议但不可直接写入

- 规划线程、SceneContract、场景节奏、公开行动空间。
- 正文中的事实候选、状态 patch、关系变化、任务变化。
- 事实抽取、总结、风险说明。

### 模型只能生成

- 当前回合的叙事正文、对白和行动参考。
- 在给定 SceneContract 和权威上下文内的可观察反应。

最重要的原则：**模型不是数据库、不是规则引擎、不是存档系统，也不是最终裁判。**

## 6. 不可回退体验验收

任何架构迁移必须保持：

1. 所有现有世界包、预设、自定义世界和研究标签入口可用；
2. 所有现有 API 分类和模型设置可用；
3. 主界面、开局界面、存档选择和手动新局可用，不自动跳入旧存档；
4. 长文本配置、SSE 即时显示和可调显示速度可用；
5. Enter 发送、Shift+Enter 换行可用；
6. 2-4 个行动选项和自由输入都可用；
7. 自动存档、手动存档、导入、导出、撤销和重生成可用；
8. Agent 监视器能显示调用阶段、输入摘要、输出、耗时、错误和 token；
9. 后端离线时明确失败，不得静默覆盖或损坏前端存档；
10. API Key 不进入前端源码、浏览器存档、调试导出或 Git。

## 7. 当前已知事实与差距

- 后端已有单次对话、SSE、供应商目录、提示词编译、状态结算、存档、结构化记忆和剧情规划接口。
- 数据库已有事实层和叙事账本的主要表，但“回合”仍主要以客户端历史和整体快照表示，尚未形成完整的服务端回合事务。
- 规划与写作已经分离，但主回合编排仍主要在 `index.html`，后端不是唯一的 Game Loop。
- 研究数据库可构建、校验和嵌入，但还不是一个有版本、有查询契约、有运行时缓存策略的题材服务。
- 测试以 Python 单元/接口测试和前端静态契约为主；浏览器级 Playwright 回归仍受环境依赖限制。
