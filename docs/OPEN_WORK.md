# 待改进项与依赖顺序

排序原则：先修复会让所有功能都不可靠的基础问题，再修复叙事质量，最后做扩展和美化。

## 2026-09-07 整体审查后的修复顺序

P2 仍为部分完成，接口存在不等于游戏链路已经接入。按以下顺序逐项修复：

1. **测试存档隔离：已完成。** 四组浏览器测试自动创建独立数据库、临时配置和随机端口，拒绝外部 `RPG_URL`；pytest 启动建表也使用临时数据库。
2. **后台任务串档：待处理。** 记忆抽取绑定会话与回合版本；摘要避免同长度历史覆盖。
3. **状态与提交一致性：待处理。** 状态接口失败不能继续成功提交；存档并发检查需原子化；历史渲染不能修改任务。
4. **结构化输出：待处理。** 流式展示、审计和记忆统一提取可见正文。
5. **规则接口接入：待处理。** 修复交易标识校验，接入游戏流程，修正质量指标与规则职责测试。
6. **文档和最终验收：待处理。** 根据实际接入和测试证据更新阶段状态；真实供应商与多设备验收仍按用户决定后置。

第 1 项验证：隔离专项与四组浏览器测试通过；后端 `445 passed, 2 failed, 3 xfailed`，两个失败仍为审查时已发现的规则职责基线失败，没有新增失败。

## P0：必须先完成

### P0-1 建立固定回放测试集（进行中）

**问题**：当前有很多单元测试，但缺少从“玩家输入 -> 记忆 -> 规划 -> SSE -> 状态 -> 存档”的完整回放。

**具体规格**：先按 [固定多回合回放基线](./REPLAY_BASELINE.md) 建立确定性协议回放器，再建立真实模型质量回放；不要直接用人工连续试玩替代。

**当前实现**：`backend/replay/runner.py` 和 `tools/run_replay.py` 已经接通真实的 SQLite、事实/叙事账本检索、提示词编译、状态结算与存档提交；`research/regression/fixtures/replay_baseline.json` 已有 10 个可重复协议场景，覆盖普通冒险、武侠拒绝、仙侠成长、现代关系、赛博日常、NPC 知识边界、资源交易、玩家分叉和穿越入口。Planner、SSE、存档恢复和浏览器验收仍需单独接入，不把协议回放误称为完整 Phase 0。

**场景最少包括**：

1. 低压日常五回合；
2. 玩家连续拒绝同一任务；
3. NPC 私聊秘密后与第三人对话；
4. NPC 承诺到期；
5. 背包/金钱交易；
6. 穿越/转生阶段；
7. 同一存档两种输入分叉；
8. 规划 Agent 失败、SSE 断流、后端离线。

**完成标准**：每个场景有固定输入、期望硬事实和指标，能在 CI/本机重复运行；当前 10/10 协议场景已达到 seed 回放条件。

### P0-2 冻结回合与存档契约

**问题**：历史、前端运行时、SQLite 账本和存档 payload 的权威关系还不够明确。

**已决定并实现**：

- **旧存档 schema 迁移**：`SAVE_SCHEMA_VERSION` + `services/save_migration.py`。
  没版本号的老存档尽力抢救并告知，声明了版本却缺字段的直接 422。
- **重新生成是覆盖，不是新分支**：`POST /sessions/{sid}/rollback` 丢弃第 N
  回合及之后的全部叙事记录，然后重跑。不这么做的话，被玩家否决那版确立的
  设定会把重写出来的新版本当成矛盾拦下来。
- **幂等键**：回合不需要单独的幂等键——「先回滚到 N 再重跑第 N 回合」天然
  不会重复累积。叙事账本另有 `_fingerprint()` 做写入去重。
- **服务端存档是主来源**：`Save.revision` 做乐观并发。客户端写回时声明基于
  哪一版，对不上回 409。自动存档遇冲突**绝不覆盖**（玩家没表达任何意图，
  静默覆盖等于替他做了个不知情的不可逆决定），只提醒一次；明确的保存操作
  询问后可以强制覆盖。本机 IndexedDB 降级为镜像，不再是权威。
- **账本原地更新可回滚**：承诺、NPC认知和人物状态在修改前写入
  `ledger_revisions`；回滚可逐级恢复旧版本，而不是只能删除本回合新记录。
- **抽取批次单事务提交**：实体/事实与事件/承诺/认知/人物状态不再分两次
  commit；任一步失败会整批 rollback。晚到的较早回合抽取也不能覆盖较新状态。
- **浏览器回合事务边界**：发送前冻结历史和完整运行时；正文、状态与服务端账本
  全部成功后才消费冲突队列并自动存档。请求或账本失败会恢复历史、回合数、
  世界时钟、状态和撤销栈；撤销/重生成等待服务端回滚成功后才修改本地记录。

**仍需决定**：

- 回合最终由服务端还是浏览器提交（与 P1-1 服务端化 Game Loop 是同一件事，
  建议合并处理）。
- 当前浏览器已经避免半提交，但正文/状态、SQLite 账本和服务端存档仍不是一个
  数据库事务；完整的“一次提交”仍要等 P1-1 的服务端 TurnService 接管。

**完成标准**：重复请求不会重复应用状态；任何失败都能恢复。

### P0-3 统一世界包来源（已完成）

世界包**正文**和规则常量已经不在前端了。`index.html` 里
`prompt:` 与 `CORE_RULES` 等规则常量均为 0 处（自定义世界那份除外，那是玩家
自己写的内容，本来就该留在前端）。提示词编译走 `/api/turn/prompt`，
`/api/worlds` 不下发 prompt 的设计已经真正生效。

公开元数据现统一存放在 `data/worlds/catalog.json`：名称、分类、技能标签、
颜色、快捷动作、预设说明和世界卡片都由前后端共同读取。后端私有的 prompt、
flavor 和 naming 独立保存在 `domain/world_content.py`，不会通过静态目录或
`/api/worlds` 下发。前端不再内嵌 `WORLDS` 和第三份 `worlds_data`。

目录契约、API 防泄漏、角色状态模板和预设引用均有测试；Playwright 已实际
加载并选择“剑与魔法”，核对 10 个世界、12 张入口卡与 6 个对应预设。

**完成标准**：添加/修改世界只改一个源文件，构建检查能发现前后端漂移。

## P1：基础架构收敛

### P1-1 服务端化 Game Loop

把 `_runTurn()` 的业务编排从单文件前端迁入 `application/turn_service.py`，前端逐步变成 UI + 事件订阅器。

**已完成第一切片**：`POST /api/sessions/{sid}/turn/commit` 以 `commit_id` 为
幂等键，在一个 SQLite 事务中提交叙事账本、会话回合号、自动存档和提交记录；
重复请求返回原结果，同一回合的不同提交会被拒绝，存档版本冲突会让整批回滚。
撤销会删除对应提交记录，使该回合可以安全重生成。普通存档写入与 TurnService
共用无提交的 `save_store` 用例，不再复制校验逻辑。

**当前状态**：上下文检索、Scene Planner、GM 裁定、SSE 写手、选项解析、状态
审计与后台记忆仍由浏览器 `_runTurn()` 编排；但后端模式的最终提交已经接入
TurnService：`commitCompletedTurnServer()` 用同一个 `commit_id` 把账本与自动存档
一次提交，成功后只写本地镜像，不再追加第二次自动存档 PUT。直接 API/后端不可用时
仍保留旧账本与本地存档降级路径。

**下一步**：让 SSE 中断、pending 恢复和存档冲突状态在监视器中显示得更清楚。当前
pending commit 已保存在 IndexedDB，重开页面或再次输入时会用同一 `commit_id` 恢复，
不会重新调用叙事模型；多设备冲突也已有本机/服务端/稍后处理选择。

### P1-2 版本化 API 与错误码

为对话、回合、规划、状态、记忆、存档定义版本和错误码；明确超时、取消、部分成功、重试和降级。

### P1-3 数据库迁移与事务

当前 SQLite 表已增多，但没有正式的 schema migration 入口。需要迁移脚本、版本表、备份和回滚测试。

### P1-4 统一 AgentRun 事件协议

规划、写手、记忆、审计和回合流水线应使用同一事件格式：`run_id`、`parent_id`、`session_id`、`turn_id`、`agent`、`stage`、`status`、`input_ref`、`output_ref`、`usage`、`error`。

**已完成一部分**：HTML 监视器已经把提交、pending 恢复和存档冲突作为 `commit`
Agent 显示，并能展开查看输入、输出、阶段耗时和深度思考。每条运行记录现在带有
`runId`、`parentId`、`sessionId`、`turnId`、`agent`、`status`、`input`、`output`、
`reasoning`、`usage` 和 `error`；回合流水线会自动成为子 Agent 的父运行。

**已完成第一切片**：新增 `agent_runs` 表、`/api/agent-runs` 写入/查询接口和
`AgentRunWrite/Out` 契约。前端在后端模式下对运行、阶段、完成和失败做尽力持久化，
打开监视器时按当前会话回读；持久化失败不会阻塞正文或回合提交。浏览器验收已用真实
会话验证写入与读取。

**仍需完成**：统一所有调用方显式传递 `session_id`、`turn_id` 和父子关系（当前旧
调用点仍有少数依赖页面上下文），并补权限、保留期限和敏感信息分级。查询接口的
回合/Agent/状态筛选与 `offset/limit` 分页第一切片已经完成。

## P2：叙事质量

### P2-1 SceneContract 回放评价

不再通过增加提示词长度判断规划是否有效。用固定分叉场景统计：玩家影响、因果连续、无关描写、钩子重发、谜语人率和首 token 延迟。

**已完成确定性切片**：质量评分器兼容三种 AgentRun 回合字段，并加入选项完整度、
典型回避表达、因果桥缺失、重复场景目的和记忆召回解释度指标；`--compare` 可以
比较同一初始局面的两条玩家分支，看正文、选项和状态候选是否真的分叉。历史坏局和
固定回放均可重复评分。

**仍需完成**：无关描写比例、因果是否真实成立、对白自然度仍不能只用关键词代替，
需要固定场景的人工标注或后续裁判层。

### P2-2 结构化选项协议

让 Writer 输出 `narrative`、`options`、`state_patch` 的结构化结果；正文展示和选项按钮不再主要依赖正则。

**兼容第一切片已完成**：后端新增 `StructuredWriterResult` 和确定性信封解析器，
提供 `/api/writer/normalize` 契约；前端识别完整 JSON 信封并直接渲染正文/按钮，
同时把 `state_patch` 纳入现有状态审计。纯文本、`【STATE】` 和缺失选项修复仍保留。
结构化写手提示词使用 `prefs.structured_writer=true` 显式开启，默认不改变旧模型行为。

**仍需完成**：在固定剧本中比较结构化与纯文本两条路径的首 token、选项完整度、状态
拒绝率和正文长度；在这组数据出来前不默认强制 JSON。

### P2-3 规则引擎优先

将交易、背包、时间、移动、检定和任务状态逐步从模型提示词中移入纯程序规则；模型只叙事。

**已有基础**：背包、资源、属性、技能、装备、NPC 态度和位置的 patch 结算已经走
`backend/app/services/game_state.py`，并有状态审计、账本和回归测试；回合计数与世界时钟
也由浏览器事务边界推进。

**新增切片**：风险检定已迁入 `POST /api/rules/check`，骰面、难度、属性/技能加值和
成功等级由 `rules_engine.py` 纯程序计算；前端只提交已确认状态，后端不可用时才保留
旧本地降级并写入诊断。

**新增契约切片已完成**：`POST /api/rules/action` 统一接收 `move`、`trade`、`quest`
三类动作。服务端会校验地点是否解锁、货币/物品是否足够、交易总价以及任务是否
重复/不存在，并只返回可审计的 `patch`、`quest_patch` 和时钟效果；正文里的
`parseQuests` 仍作为旧存档/纯文本兼容路径，不再是新规则契约的唯一来源。

**仍需完成**：把浏览器自然语言意图识别映射到该契约，并在结构化写手模式下优先
消费 `quest_patch`；这属于下一阶段的前端事件编排，不应再复制一套规则。

### P2-4 记忆压缩与检索可解释

服务端摘要必须带时间范围、来源和版本；检索结果必须能说明为什么加入/排除，避免“向量召回了但 NPC 不该知道”。

**第一切片已完成**：事实、事件、承诺、人物状态和 NPC belief 的 trace 现在都带
`source`、`turn`、`version` 和 `reason`；评分器会统计带理由的召回覆盖率。旧导出
没有 trace 时返回空指标，不误报。
