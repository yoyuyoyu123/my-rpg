# 无界项目文档中心

这组文档是项目的**开发基线**，用于把需求、架构、实现、测试和发布流程固定下来。它们描述的是“当前实现”和“目标架构”之间的差距，不把计划写成已经完成的功能。

## 阅读顺序

1. [项目基线](./PROJECT_BASELINE.md)：产品边界、当前运行链路、权威数据和已知事实。
2. [实现原理与架构](./ARCHITECTURE.md)：前端、后端、数据库、模型 Agent 和存档的职责边界。
3. [功能矩阵](./FEATURE_MATRIX.md)：现有功能、代码位置、验证方式和当前状态。
4. [标准开发生命周期](./DEVELOPMENT_LIFECYCLE.md)：从需求冻结到可发布版本的阶段、入口条件、出口条件和质量门。
5. [固定多回合回放基线](./REPLAY_BASELINE.md)：场景 fixture、确定性回放、真实模型回放、指标和硬性门槛。
6. [待办与风险](./OPEN_WORK.md)：按依赖关系排序的缺口，避免继续随机修补。
7. [学术对照地图](./RESEARCH_MAP.md)：我们踩过的坑对应的研究领域、可直接借鉴的做法、以及现成的理论骨架。遇到「模型就是不照做」时先查这里，再决定改提示词还是加程序保证。

## 规范优先级

发生冲突时按以下顺序处理：

1. 用户明确确认的产品体验与安全边界；
2. [项目基线](./PROJECT_BASELINE.md)中的不可回退验收项；
3. API/Pydantic 契约与数据库模型；
4. 本架构文档和阶段计划；
5. 具体提示词、模型偏好和临时实现。

提示词不是架构。任何提示词调整都必须说明它依赖的状态、输入契约、输出契约和回归场景。
