# 叙事质量度量

## 为什么有这份东西

到 2026-08-24 为止，这个项目有近四百个单元测试，**全部在检查提示词的结构**
——某句话在不在提示词里、某个字段有没有被清洗。没有一个在测叙事的质量。

后果是玩家在充当测试环境。过去八轮的循环是：

    玩家玩 → 玩家报告 → 读日志定位 → 改 → 玩家再玩

代价很具体：详略那一版通过了全部测试、也做了 HTTP 实测，玩家玩下来第一句话
是「非常之无聊」。**「实测过了」只证明字符串拼对了，不证明玩起来变好。**

这份度量的目的就一个：**让改动能在推给玩家之前先被自己检验一遍。**

## 用法

```bash
# 给一次导出打分
backend/.venv/Scripts/python.exe tools/score_session.py 监控导出.json --world fantasy

# 批量扫一个目录
backend/.venv/Scripts/python.exe tools/score_session.py --dir ~/Downloads

# 对照玩家原话验证指标本身是否可信
backend/.venv/Scripts/python.exe tools/score_session.py --validate --dir ~/Downloads
```

输入是前端「导出 Agent 监控」得到的 JSON。

## 设计取舍

### 一、优先确定性，不急着上模型裁判

玩家抱怨过的问题，**大部分不需要模型当裁判**——结构化数据里就有：穿越用了
几回合、连着几幕没冲突、一张卡挂了几个回合、详略分布如何。这些可复算、
零成本、不受裁判模型自身波动影响。

只有少数确实需要判断（这段正文好不好看、对白自不自然），那部分留给后续的
裁判层。**先把能确定算的算准**，否则一开始就把噪声引进来，指标本身不可信，
后面所有结论都站不住。

### 二、指标必须独立于提示词书写

`WORLD_MARKERS` 是另写的一套词表，**故意不引用 `domain/worlds.py` 的 `flavor`
字段**。拿提示词原文去匹配正文，测的只是「模型有没有复读提示词」，不是
「世界有没有立起来」。

同理，`QUIET_STREAK_BAD` 等阈值在度量模块里写死，不从 `story_planner` 导入
——指标不该跟着被测代码一起变，否则把规划器的阈值调宽就能让指标变绿。

### 三、指标可不可信，看它能不能标出已知的坏局

这是整件事的关键。`tools/score_session.py --validate` 拿玩家的原话当真值，
检查指标能否复现他的判断。当前结果 **5 命中 / 1 漏报**：

| 对局 | 玩家原话 | 指标判定 |
|---|---|---|
| 08-22 15:24 | 推进依然慢得要死 | 走马观花 8 幕；穿越从未发生（18 回合） |
| 08-23 05:57 | 依然不穿越 | 走马观花 4 幕；穿越从未发生（14 回合） |
| 08-23 07:00 | 终于能穿越了，但隔了一回合 | 走马观花 5 幕；世界没立起来 |
| 08-23 13:11 | 穿越还是慢，虚空里走半天 | 转移拖沓（阈限第 4 → 落地第 7）；走马观花 9 幕 |
| 08-23 14:37 | 非常之无聊，没有任何冲突 | 走马观花 6 幕；世界没立起来 |
| 08-23 14:58 | 中式的榆树村；没显示出剑与魔法 | 世界没立起来；**中式地名漏报** |

三局的裁剪版冻结在 `research/regression/sessions/`，由
`backend/tests/test_quality_metrics.py` 当回归语料，跟着单元测试一起跑。

## 当前指标

| 指标 | 含义 | 触发条件 |
|---|---|---|
| `quiet_streak_max` | 连续多少幕 `conflict` 为空 | ≥3 报「走马观花」 |
| `transit_turns` | 阈限到落地占了几个回合 | >3 报「转移拖沓」 |
| `crossing_turn` | 第几回合落地 | 从未落地且已玩 >8 回合报「穿越从未发生」 |
| `flavor_hit_rate` | 题材特征词在正文里的命中率 | <20% 报「世界没立起来」 |
| `cn_place_names_in_western_world` | 西式世界里的中式地名 | 非空即报 |
| `scene_span_max` | 一张场景卡最多挂了几个回合 | ≥8 报「场景拖沓」 |
| `forced_takeovers` | 程序接管了几次 | 观察项，高说明模型不配合 |
| `narration_mix` | 详写/略写/省略的分布 | 观察项 |

## 已知局限（不掩盖）

**1. 专名滞后一到两个回合。**
`cn_place_names_in_western_world` 取自事实库的结构化条目
（`[place]`/`[person]`/`[faction]`），那是模型带上下文抽取并分好类的，
比正则准得多——但刚在正文里出现的名字要下一回合才进事实库。
所以「榆树村」在那局漏报了：它只在最末一回合出现过。

试过正则切正文，在真实文本上匹配出「半天到镇」「地址在城」「她榆树村」
——中文没有词边界，词干必然切错。那一版**会给出正确结论但理由是错的**，
比漏报更危险，所以放弃了。这条在测试里标成 `xfail(strict=True)`：
它是已定位的局限，不是没想到的情况；哪天修好了测试会主动提醒。

**2. `TRANSIT_SLOW_TURNS` 只由两局标定（n=2）。**
手上只有两局真正落了地的穿越，3 和 4 之间那条线基本是照着这两个点画的。
这是全部阈值里最弱的一条，它的判定当线索用，不当结论。攒够对局后重标。

**3. 只测「有没有」，不测「好不好」。**
正文写得美不美、对白自不自然、人物立不立得住，现在完全测不到。
那需要模型裁判，是下一步。

**4. 词表覆盖有限。**
`WORLD_MARKERS` 每个世界十来个词，是手写的。命中率低确实说明世界没立起来，
但命中率高不等于写得好——模型堆砌名词也能刷高。它是**下限检测**，不是评分。

## 下一步

1. **模型裁判层**：对可判定的问题提问（这一幕有没有真正的冲突？名字符不符合
   本世界的命名规矩？），而不是让它打一个笼统的分。参考 `RESEARCH_MAP.md`
   第八节列的 NarraBench / NARRA-Gym。
2. **接进回放**：现有 `tools/run_replay.py` 用的是预置回复，测程序不测模型。
   需要一条真实模型回放的路径，跑完自动打分。
3. **改动前后对比**：同一份剧本、同一个种子，改动前后各跑一次，比较指标。
   这才是「改完能自己验一遍」真正成立的形态。
